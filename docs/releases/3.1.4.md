# GTNH Planner 3.1.4 — Engineering changelog

September 11, 2026. Changes since 3.1.2, production commit `453d91c`.

## Release scope

This release contains every change since the deployed 3.1.2 build. The work previously listed under the unreleased 3.1.3 entry ships together as 3.1.4. It covers machine calculations, configuration controls, material accounting, the machine list, structure pictures and resource colors. These changes use the existing GTNH 2.9 dataset; no dataset rebuild or recipe editing is required.

## Wiring preserves recipe quantities

A connection used to be able to copy the supplying port's batch amount into the receiving recipe's saved input choice. Changing the plumbing could therefore change the apparent recipe without changing its outputs. Connections now take quantities from each receiving recipe slot, applying a conversion ratio only for a supported ingredient alternative. The feeder's batch size is never the receiving machine's consumption requirement.

## Electric Blast Furnace: alumina and oxygen

The reported aluminium plan stored a five-dust alumina override on a recipe requiring ten, while still producing four ingots and 3,000 L of carbon dioxide from that batch. The correct batch remains 10 alumina dust plus 3 carbon dust. Buffer insertion uses the same corrected connection rule: a recipe requiring 1,000 L oxygen per dust keeps that ratio after a buffer is added. At 201.4 dust/hour, its oxygen consumption is 201,400 L/hour, regardless of a feeder producing 2,000 L per batch. Removing or inserting a drawer must not rewrite these proportions.

## Saved wired input choices are repaired on load

The common plan-loading path reapplies the receiving slot's quantity for matching saved wired choices. This repairs the reported five-alumina override as well as older partially selected crafting ingredients. The underlying recipe remains read-only. Concrete ingredient choices and separately selected variants are retained, and a repaired dictionary connection is moved to the matching concrete port so the wire survives reload. This repair concerns wired choices; it is not a blanket replacement of every saved override.

## Auto Workbench: grouped ingredients remain one demand

Repeated crafting slots were grouped visually, but a wire could select only the first slot and leave another slot asking for an unresolved ore-dictionary ingredient. The reported resistor recipe then acquired a duplicate, unsatisfied input row. A wire now selects all repeated slots in the addressed ingredient row while preserving each slot's own amount and NEI position. The resistor recipe displays four ingredient rows and consumes two Fine Copper Wire per resistor. Unselected dictionary rows show a real item name and icon; non-consumed slots, separately chosen variants and other sections of a shared machine retain their own choices.

## Neutron Activator: arbitrary pipe height

Pipe height is now a directly editable integer starting at four, rather than a selector ending at twelve. Each additional layer applies the game's 0.9f duration factor. Whole-tick durations round upward; below one tick, the machine uses floor(1 / duration) simultaneous operations, bounded by the game's integer limit. A 400-tick recipe takes 173 ticks at height 12, 21 at height 32, and reaches 61 operations per tick at height 100. Extra voltage does not buy ordinary overclocks. Accelerator hatch power remains unmodeled, and the reported products assume neutron kinetic energy is inside the recipe's permitted range.

## Utupu-Tanuri: both recipe modes use the same machine

Vacuum Furnace recipes now resolve to the existing Utupu-Tanuri calculation, alongside Multiblock Dehydrator recipes. Previously the vacuum recipes bypassed the curated machine definition and its coils. Both modes receive 2.2 times base speed, half base EU/t and up to four parallels, limited by available power. Excess coil heat grants the 5% energy discount per 900 K and a perfect overclock per 1,800 K. The coil selector starts at the recipe's required heat: dehydration can genuinely require zero K, while vacuum recipes can require much more. The 7,200 K sulfur-froth example at UV and four parallels takes 272 ticks with Naquadah coils or 136 ticks with Trinium coils.

## Hyper-Intensity Laser Engraver: one real laser-source selector

The duplicate laser controls have been replaced by one selector containing the 46 registered voltage/amperage combinations. Laser amperage sets the structural parallel ceiling through floor(cube root of amps): 65,536A permits 40 parallels, while the Legendary UXV source has 536,870,912A and a ceiling of 812. The source voltage separately gates recipes and caps overclocking at one tier above the source. Its 3.5 times speed and 0.8 times EU modifier remain. The laser source supplies no operating energy; the card's energy hatches must still pay for the usable parallels and overclocks. Tooltips distinguish those roles and the assumption of matching glass. Number searches work with or without commas, and changing sources keeps the card dimensions stable.

## HILE: old source settings have a defined migration

A previously saved real laser source takes precedence over the obsolete dummy amperage control. Amperage-only saves resolve to the lowest registered source voltage supporting those amps because they never recorded the source voltage. For example, 65,536A resolves to UHV. If the actual machine uses a higher-voltage source at that amperage, select that source to recover its higher overclock ceiling. A source that is too weak for the recipe now stalls the machine with a source-specific explanation instead of suggesting that more operating amps will solve it.

## PrAss: normal assembly and precise assembly are calculated separately

Both modes now expose voltage and amperage controls and use the curated multiblock calculation. In normal Assembler mode, the Precise Auto-Assembler MT-3662 runs at twice base speed; Imprecise and Mk-I through Mk-IV unit casings provide parallel capacities of 16, 32, 64, 128 and 256. Available energy pays for those parallels before overclocks. Dedicated Precise Assembler recipes instead run at base speed with one parallel, and their unit casing is a recipe requirement rather than a throughput multiplier. The normal handler's UHV controller unlock no longer incorrectly becomes the minimum hatch voltage for a low-tier recipe.

## PrAss: machine casing limits working voltage

A separate Machine casing control now caps working voltage before amperage is applied. More amps cannot make a recipe above that voltage cap valid. UHV casing removes the cap and is the default for older cards, preserving the previous assumption of sufficient casing. Unit casing and machine casing perform different jobs and are both shown. EV-or-better glass remains an assumed construction requirement. Multi-amp and laser energy supplies use the card's power controls; they do not act as a separate HILE-style laser source.

## Liquid Fluoride Thorium Reactor: Fuel 3 produces the correct power

Fuel 3 previously showed 32,768 EU/t, or 1A LuV, instead of 524,288 EU/t, or 1A UV. The fuel's energy density was correct, but parsing a tier name missed the lowercase letter in LuV and selected a fallback. Output now comes directly from numeric energy density at the reactor's fixed 1 L/s fuel consumption, divided by 20 ticks/s. Fuels 1, 2 and 3 produce 32,768, 131,072 and 524,288 EU/t respectively. Saved reactor cards update through the normal load-time recipe rebuild; Fuel 3's corrected electrical output is sixteen times its previous displayed value.

## Brick Coke Oven: no free voltage overclocks

The old Coke Oven name also matched the Industrial Coke Oven definition, allowing a saved voltage setting to accelerate an unpowered brick oven. A 1,800-tick recipe could incorrectly become 225 ticks at EV. Brick ovens now retain their recipe duration, one parallel and no ordinary overclocking. Industrial Coke Ovens retain their powered calculation and slices control. The reported industrial plan explicitly stored a 4,096 EU/t budget, which is 2A EV; that budget is preserved. A single regular EV hatch should be configured as 1A, or 2,048 EU/t. This release does not halve explicit saved power budgets or remove either oven family.

## Machine list: one row per physical card

Cards with identical recipes and settings no longer have their figures combined into one child row. Machine-name headers and the indented count/power layout remain, with extra spacing after the tree connectors. Build reads each card's configured machine count. Solve and Pool read the sum of that card's solved section requirements, preserving fractions, zero demand and requirements above the stored count. Parallel processing scales throughput and power, not the physical machine count. Row clicks focus that one card, and its checklist toggle affects that card alone. Crop cards continue to count harvesters rather than seeds.

## Machine list: peak and average power follow the same card

A shared machine remains one list entry even when it runs several recipes. Its peak draw comes from the hungriest section, while average draw is weighted by each section's machine requirement in Solve/Pool or time share in Build. Steam use and generation follow the corresponding count rule. Verification with three Wiremill cards gives Build counts of 2, 3 and 4, totaling nine machines and 36 EU/t. Solve and Pool requirements of 0.125, 6.25 and 101.375 remain fractional, totaling 107.75 machines and 431 EU/t, rather than being rounded up or replaced by stored counts.

## Structure pictures and resource colors

Chemical Plant, Boldarnator and Industrial Sledgehammer now display their own structure images; the three existing image files had been assigned the wrong names. The inaccurate Vacuum Furnace structure image has been removed, so that machine uses its real controller icon. Drawers, input/output totals, target amounts, target editors and trend lines now use the shared resource colors: red for inputs or deficits and mint green for outputs or surplus. Buffers and trash keep their neutral steel treatment, and explicit player-applied drawer colors still take precedence.
